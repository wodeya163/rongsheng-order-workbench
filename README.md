# 榕盛商贸订单管理工作台 - 使用说明

> **当前版本 v3.5.4（2026-11-24）**：**源代码上 GitHub，自动更新改走 GitHub Releases** —— 更新源支持 `github:owner/repo`（可加 `@v3.5.4` 锁版本），程序直接读公开仓库最新 Release 里的 `manifest.json` 与安装包，免登录、无需 token、不消耗 API 配额；旧版本地发布目录源升级后自动切到 GitHub 并留作**离线备用源**（GitHub 不可达时自动回退）。发布侧新增 `tools/publish_github.py`：SHA256 实算校验 → 生成 GitHub 版清单 → 建/复用 Release → 上传 zip + manifest.json → 回读资产与直链核对。详见 §「GitHub 自动更新」。回归 `test_updater_github_v354.py` 23 项；schema 仍 v7、零 DDL 改动，`data/` 原位保留。
> **v3.5.3（2026-11-19）**：**两段式建单** —— 新增订单只创建订单头，明细不再必填；创建后在订单管理里选中该单，点「录入订单明细」（9 字段表格，一次可存多行）或「导入订单明细」（CSV / Excel，只需「物资名称 + 数量」两列，表头不在首行自动定位）补录。两个动作与「新增订单」同处左侧导航 / 业务菜单 / 主界面快捷栏，选中订单右键也能直达。**修复了旧「导入订单」把一张明细表拆成多张空壳订单、或首行是标题就整表失败的问题**（详见 §订单明细两段式录入 v3.5.3）。
> **v3.5.2（2026-11-19）**：**导入即自动应用** —— 采购合同导入成功后，若合同明细表全部行高置信匹配、零未匹配、金额对账零差额且数量守恒，物资分配（数量 / 含税单价）直接写入台账，省掉「物资分配 → 保存分配」那一步；任一条件不满足只提示原因、绝不写库。开关在采购合同管理窗口「导入合同」右侧，默认开启、可随时关闭。

> **v3.5.0（2026-11-18）**：新增订单盈亏与多供应商采购归集 —— 一订单多项物资可分签不同供应商合同，自动汇总销售价 / 采购价、计算利润率，并生成柱线组合图（可导出 PNG 与 Excel）。

> **自动更新 v3.1.0（2026-11-08）**：程序获得**半自动更新**能力（方案 B，保持绿色版形态）——
> ① **发布侧**：`python tools/release.py --note "更新说明"` 一条命令 = 打包 → 压 zip（自动排除
> data/logs/更新目录）→ SHA256 → 生成 `manifest.json`（dist/release/ 下，放更新源即完成发版）；
> ② **用户侧**：启动 3 秒后后台拉清单比对版本（**帮助 → 设置更新源…** 填 manifest.json 的
> 本机/共享路径或网址，存 `data/updater.json`；无源/出错/无更新一律静默），有新版弹窗展示
> 更新说明 → 点「立即更新」→ 下载 zip（SHA256 校验 + 进度条）→ 解压 → **新版 exe 以
> `--apply-update` 模式充当更新器**执行目录交换：`data/`（数据库/附件/日志）**原位保留**、
> 旧目录进 `_old_*` 备份（滚动清理）、任何一步失败**自动回滚**旧程序照常可用 → 自动重启进新版。
> manifest.json 字段：`version / zip / sha256 / note / date`；设计见 §6.21。
> **云盘文件读取修复 v3.1.1（2026-11-08）**：解决「从资源管理器选 OneDrive 文件后读不出来」——
> 根因是 Windows 按需文件（Files On-Demand）本地只留壳（`RECALL_ON_DATA_ACCESS` /
> `RECALL_ON_OPEN` / `OFFLINE` 属性位），首次读数据要触发云端水合，离线时无限阻塞或抛
> `OSError Errno 22`；且 Qt 自绘文件框不走 Shell，看不到云盘「仅联机」状态、侧边栏也没有云盘入口。
> ① **文件框默认改 Windows 资源管理器原生对话框**（`theme.use_native_file_dialog()`），
>    侧边栏自动补 `OneDrive / OneDriveCommercial / %USERPROFILE%\OneDrive` 目录；
>    离屏自检用 `QT_QPA_PLATFORM=offscreen` 自动回退自绘，也可用 `PQS_FILE_DIALOG=qt` 强制；
> ② 新增 `v2/core/cloudfile.py`：`ensure_readable()` 在守护线程里把云占位文件复制到
>    本地缓存副本（按 路径+大小+mtime 命中复用，文件名/扩展名不变），主线程最多等 30 秒、
>    每 50ms 刷一次界面事件，超时/大小不符抛可读错误（提示资源管理器右键
>    「始终保留在此设备上」），**绝不无限卡死**；
> ③ 全链路接入：文件框选中后预热、`docread.read_source()` / `excelio.import_rows()` /
>    订单排产两处附件复制 / 更新清单 `fetch_manifest()` / 本地更新包 `download_zip()`。
> 路径字段仍存用户选的**原始云盘路径**，不改变业务语义；设计见 §6.22，回归 `test_cloudfile.py` 32 项。

## 📋 功能特性

### 1. 产品管理
- **新增产品**：填写完整表单，支持图片/图纸上传
- **编辑产品**：双击表格或点击"编辑"按钮
- **删除产品**：选中后删除，有确认提示
- **查看详情**：点击"查看"按钮查看完整信息

### 2. 数据字段
| 字段 | 说明 | 必填 |
|------|------|------|
| 产品名称 | 产品完整名称 | ✅ |
| 规格型号 | 产品规格型号 | |
| 产品分类 | 自由输入分类 | |
| 对外报价 | 对外报价（元） | |
| 报价比率 | 如 0.85（85%） | |
| 询价数量 | 询价数量（个） | |
| 询价单位 | 下拉选择常用单位（个/台/套/米…），也可自定义 | |
| 采购询价 | 采购价格（元） | |
| 投标项目 | 关联项目名称 | |
| 是否中标 | 下拉选择：是 / 否（用于中标分析） | |
| 产品描述 | 详细描述 | |
| 产品图片 | 支持 PNG/JPG 等 | |
| 产品图纸 | 支持 PDF/DWG 等 | |

### 3. 核心计算
**报价价格 = 采购询价 ÷ 报价比率**

- 采购询价：1000元
- 报价比率：0.85（85%）
- 报价价格：1000 ÷ 0.85 = 1176.47元

### 4. 搜索功能
支持多字段组合搜索：
- 按产品名称（模糊匹配）
- 按产品分类
- 按规格型号
- 按投标项目
- 按是否中标（是 / 否 / 全部），便于筛选已中标或未中标的产品

### 5. 价格汇总
实时显示：
- 产品总数
- 采购总额
- 报价总额
- 毛利（报价总额 - 采购总额）

### 6. Excel导出
- 导出当前搜索结果或全部数据
- 包含所有字段、计算列（对外报价）与合计行
- 动态列宽 + 带样式的.xlsx文件

### 7. Excel导入（新增）
- 从 .xlsx 按中文表头批量导入产品（含询价单位、是否中标）
- 自动跳过缺少名称或"合计"行，返回成功/跳过统计

发布包以 **GitHub Release 资产**分发，程序端直接读资产直链，不再依赖本机共享目录。

### 用户侧（一次配置，之后全自动）

| 场景 | 做法 |
|---|---|
| 新机器首次运行 | 「帮助 → 设置更新源…」已预填 `github:wodeya163/rongsheng-order-workbench`，直接点「保存」即可 |
| 从 v3.5.3 及更早版本升级 | 升级到 v3.5.4 后，旧的本地发布目录源会**自动切到 GitHub**（只做一次），旧源写入 `data/updater.json` 的 `fallback` 作为离线备用 |
| 手动切换 | 「帮助 → 设置更新源…」里点「填入 GitHub 自动更新（推荐）」，或自己填 `github:owner/repo`、`github:owner/repo@v3.5.4`（锁定版本） |
| 断网 / GitHub 不可达 | `check()` 自动回退 `fallback` 清单（原本地发布目录），不会把客户端卡死 |

启动 3 秒后后台检查；有新版弹窗展示版本对比与更新说明 →「立即更新」= 下载（进度条 + SHA256 校验）→ 解压到 `_update_staging` → 新版 exe 以 `--apply-update` 充当更新器做**目录交换** → `data/`（数据库 / 附件 / 日志）原位保留、旧目录进 `_old_*` 备份、失败自动回滚 → 自动重启新版。

支持三种更新源，全部保持兼容：`github:owner/repo` / `http(s)://…/manifest.json` / 本机或 UNC 路径。

### 发布侧（维护者）

```powershell
# ① 升版本号（v2/__init__.py 的 __version__ + version_info.txt），改完跑回归
py -3.13 tools\verify.py --no-exe

# ② 打包 + 出本地发布产物（dist/release/ 下 zip + manifest.json）
py -3.13 tools\release.py --note "本次改了什么" --skip-build   # 改过源码则去掉 --skip-build
Copy-Item dist\release\* D:\Programs\ProductSuite_发布\ -Force   # 本地通道：供尚未升级的旧版收更新

# ③ 一键发 GitHub Release（凭据从本机 git 凭据管理器读，不落盘、不回显）
py -3.13 tools\publish_github.py
py -3.13 tools\publish_github.py --dry-run                       # 只校验 SHA256 与打印计划

# ④ 推送源码
git add -A && git commit -m "v3.5.4 …" && git push origin main
```

`publish_github.py` 会：按 `manifest.sha256` **实算校验** zip（不一致直接拒绝）→ 把清单里的 `zip` 改写成该 Release 的资产绝对直链（客户端因此无需调 GitHub API）→ 创建或复用 `tag=v<版本>` 的 Release（同名旧资产先删）→ 上传「安装包 zip」+「manifest.json」→ 回读资产大小与固定 tag 直链内容逐项核对。

清单字段仍是 `version / zip / sha256 / note / date`；本地发布目录那份 `zip` 是相对文件名，GitHub Release 那份 `zip` 是绝对 URL，两条通道互不干扰。

### 安全与边界

- 安装包完整性由 **SHA256** 兜底；GitHub 源的清单下载地址额外限定在 `github.com` / `githubusercontent.com` 域内。
- 程序内**不内置任何 token**；公开仓库匿名可读，客户端不需要凭据。私有仓库的 Release 资产需要 token，因此发布仓库保持公开。
- 仓库只含**源代码、设计文档与界面预览**；`data/`（真实 ERP 库与附件）、`dist/`、`build/`、`archive/`、根目录真实询价单 / 图纸 / 销售汇总、迁移台账一律由 `.gitignore` 排除，文档中的客户全称与业务单号已做示例化脱敏。
- `data/` 不进更新包，升级只换程序文件，业务数据零改动。

### 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 「无法从 GitHub 发布仓库读取更新清单」 | 仓库尚未发布 Release，或 Release 里缺 `manifest.json` 资产；离线时会自动回退本地备用源 |
| 「更新包下载中断」 | 网络断开 / CDN 超时（读超时 60 秒）；半截包已自动删除，重试即可 |
| 「SHA256 不匹配」 | 清单与 zip 不是同一批产物；重新执行 `release.py` + `publish_github.py`，切勿手工改 zip |
| 想回滚到指定版本 | 更新源填 `github:wodeya163/rongsheng-order-workbench@v3.5.4`，锁到该 Release |
