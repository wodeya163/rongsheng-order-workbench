## 二、主窗口拆分（P2-2）

### 拆分结果

|---|---:|---|
| `v2/ui/main_window_v2.py` | **618** | 窗口骨架、菜单、三栏布局、动作包装 `_run/_require`、启动入口 |
| `v2/ui/panels/views.py` | 668 | 六个视图的表格构建、刷新、SQL 过滤与分页、KPI、视图切换 |
| `v2/ui/panels/maint_actions.py` | 396 | 溯源穿透、备份/恢复/体检、编辑/作废/删除、审计与操作人 |

| `v2/ui/panels/bid_code_actions.py` | 202 | 询报价与询配码的全部动作 |

### 三条保证

1. **行为不变**：方法体逐字迁移（只去掉类内缩进），未改任何判断、SQL、文案；
2. **旧路径可用**：`MainWindowV2`、`ACTION_GROUPS`、`VIEW_NAMES`、`fill_table`、`selected_id`、`select_id`
   仍从 `v2.ui.main_window_v2` 导出，测试与脚本无需改动（`test_33` 锁死）；
3. **边界可验**：`panels/*` 禁止反向引用主窗口（`test_31`），Mixin 之间方法不得重名（`test_34`）。

拆分方式：用一次性脚本按「`def` 方法块」机械切分 + 固定去缩进，切完立刻跑离屏建窗与全量测试；
期间发现的唯一问题是缩进层级（`elif` 比 `if` 多缩了 4 格）与主窗口缺 `QGridLayout` 导入，均由测试暴露后修正。

## 三、表名白名单（P2-4）

```python
# v2/core/db.py
def insert(self, table, data):
    table = tbl.check(table)            # 不在 core/tables.py 里 → TableNameError
    ...
```

| 措施 | 说明 |
|---|---|
| `core/tables.py` | 16 张表集中登记（业务表 13 + `doc_sequence`/`audit_log`/`schema_meta`），`check()/is_valid()` |
| 列名校验 | `INSERT/UPDATE` 的键必须是 `[A-Za-z0-9_]`，`"doc_no) VALUES (1); --"` 直接拒绝 |
| 反向核对 | `missing_from_declaration()` / `undeclared_in_ddl()` 在测试里比对 `schema.sql`，漏登记即失败 |

实测：`"orders; DROP TABLE orders"`、`"sqlite_master"`、`""`、`None`、`"ORDERS"` 全部被拒；
正常 CRUD 与 213 项测试不受影响。

## 四、查询方案（P2-5）

| 环节 | 实现 |
|---|---|
| 存储 | `query_presets(id, name UNIQUE, view_key, filters JSON, sort_order, created_by, created_at)`，迁移 v4 建表 |
| 预置 | 待发货订单 / 逾期未交 / 7 天内到期 / 还有可排量（仅当表为空时铺，删掉不会自己长回来） |
| 服务 | `save()` 同名默认报 `DuplicateError`，`overwrite=True` 覆盖；`delete()` 幂等；坏 JSON 回落空条件 |
| 界面 | 查询面板顶部「方案」下拉 + 「存为方案…」+「删除」；套用时自动切到方案所属视图并重查 |
| 边界 | 只存条件、不存结果、不写审计；空条件不落库（避免方案里躺一堆 `""`） |

## 五、交期预警（P2-6）

- **口径**：以 `orders.required_date`（交货日期）为准，比较「今天」；
  **已交付 / 已验收 / 关闭 / 作废** 不催交；「临期」= 今天起 7 天内。
- **两处一致**：表格显示走 `query.due_state()`，筛选走 `query.due_clause()`（SQL），
  同一份 `_DUE_DONE_STATUS`，`test_22` 用同一天的数据交叉验证两边结果相同。
- **界面**：订单表新增「交期状态」列（逾期红色加粗 / 临期橙色）；结果区徽标追加「· 逾期 N / 临期 M」；
  查询面板新增「交期」下拉（全部 / 已逾期 / 7 天内到期 / 未到期）。
- **真实库实测**：306 单中 **逾期 37 单、临期 0 单**（数据为 2024-2026 历史单，交期多在过去）。

## 六、一键校验与 CI（P2-3）

```
py tools/verify.py            # 六步全量（有 dist 就跑打包自检）
py tools/verify.py --fast     # 只跑语法 + 单测（改代码时）
py tools/verify.py --no-exe   # 不碰 exe（CI 用这个）
py tools/verify.py --build    # 全量通过后重新打包
```

| 步骤 | 内容 | 2026-11-07 19:15 实测 |
|---|---|---|
| 1 | 语法编译（`compileall` v2 全部 60 个文件） | PASS 0.9s |
| 2 | `pytest v2/tests` | PASS 213 passed + 24 subtests（32.8s） |
| 3 | v1.5 回归 `tests/test_core.py` | PASS 36/36（2.8s） |
| 4 | exe `--check` | PASS 16 张表 / docx / PDF / OCR chi_sim+eng（5.5s） |
| 5 | exe `--ui-check` | PASS 菜单 7 组 / 结果页 6 / 操作分组 6 / 查询条件 7 类（2.3s） |
| 6 | exe `--parse-check` 四通道 | PASS xlsx / docx / pdf / png 全部识别（11.9s） |
| — | 合计 | **6/6 通过，61.4s** |

**踩到的坑**：`py tools/verify.py` 时 `sys.executable` 指向工具链自带的精简 Python，里面没有
pytest/PySide6，直接用它跑第二步会误报 `No module named pytest`。现在脚本会优先挑
「能 `import pytest, PySide6`」的解释器（环境变量 `PRODUCT_SUITE_PYTHON` 可强制指定），并打印实际使用的路径。

CI：`.github/workflows/ci.yml`（Windows + Python 3.13 + pip 缓存）跑 `verify.py --no-exe`，
失败时上传 `logs/` 与 `.pytest_cache`；本地与 CI 共用同一入口，避免两套标准。

## 九、遗留（本轮未做，属业务功能而非整改）

1. **工序排产 / 产能甘特图**：`production_tasks` 表已建但未接界面，需要先定「工序口径」
   （几道工序、工时来源、是否按设备产能倒排），属需求澄清类工作，不宜在整改里拍脑袋实现。
2. **多用户 / 共享库**：当前按单机单用户设计（单实例互斥 + WAL 不跨网络），
   真要多人用需要换 PostgreSQL 并加登录体系，工作量在 1-2 周量级。
3. **主窗口之外的 UI 边界**：`dialogs.py` 仍有 1,500 行（多为独立对话框类），
   后续如果要继续加功能，建议按「对话框族」再分一次包。

## 十、兼容性提醒

- 数据库结构升到 **v4**：老库首次打开会建 `query_presets` 并铺 4 个默认方案，**不改动任何业务表**。
