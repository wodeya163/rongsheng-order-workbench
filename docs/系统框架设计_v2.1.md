## 1. 本次修订了什么（先看这张表）

| # | v2.0 的错误理解 | v2.1 正确口径 | 代码落点 |
|---|---|---|---|
| 1 | 询配码单由**中标询价单转换生成** | 询配码与询报价**毫无关系**，是独立域 | 删除 `code_orders.source_quote_id`、`code_items.source_quote_item_id`、`convert_to_code_order()`；新 `code_projects` / `code_items` 无任何 bid/quote 外键 |
| 2 | 排产直接挂**询配码明细项** | 排产挂**订单明细**，询配码只是溯源终点 | `production_links.order_item_id` 取代 `code_item_id` |
| 3 | 询配码明细数量参与守恒 | 询配码明细数量是**虚值**，只统计、不约束 | `code_items.qty_reference` 不设 CHECK、不进任何守恒公式 |
| 4 | 数量守恒锚点是 `code_items.qty` | 锚点是**订单明细 `qty_ordered`（实值）** | `Σallocated_qty ≤ order_items.qty_ordered` |
| 5 | 缺了「用户下单」环节 | 新增**订单域**作为排产枢纽 | `orders` / `order_items` / `OrderService` |
| 6 | 询报价只是"产品表" | 询报价是**招投标项目统计**，只有中标项目可关联排产 | `bid_projects` / `bid_items`，`production_projects.source_bid_project_id` + 中标校验 |
| 7 | 单号 `XJ-` 询价单 | 招投标项目 `ZB-`，新增订单 `DD-` | `core/codegen.py` |

**一句话**：v2.0 画的是「询价 → 询配码 → 排产」；v2.1 是两条互不干扰的轨道汇入排产——
**询配码项目（虚值）→ 提交用户 → 订单（实值）→ 排产**，外加**中标项目作为排产的来源标签**。

## 2. 业务口径逐条落地

| 张哥原话 | 建模落点 |
|---|---|
| 询报价模块主要用于统计**招投标项目的数据和项目** | `bid_projects` 单据头（项目名/客户/招标编号/投标日期/状态/负责人）+ `bid_items` 明细；沿用 `对外报价 = 采购价 ÷ 报价比率` |
| **只有中标的项目才会关联到生产排产** | `production_projects.source_bid_project_id`（可空）；`ProductionService._assert_won()` 在 `create_project` / `link_bid_project` 两处硬校验 `bid_projects.status == '中标'`，否则抛 `StateError` |
| **询配码和询报价关联模块无关系，不来源于中标询价单** | `code_projects` / `code_items` 两表无任何指向 `bid_*` 的列或外键；`BidService` 不提供任何转换接口（测试 `test_02` 断言） |
| 询配码模块用于**统计询配码项目**，文件**直接提交给用户** | `code_projects`（`file_path` / `version` / `submit_date` / `status`）+ `submit()` 提交动作；`PartCodeService.statistics()` 出项目统计 |
| 用户根据需求**下单**，产生**订单**并进行管理 | 新增 `orders` / `order_items`；`OrderService.create_from_code_project()`、`confirm()`、`summary()` |
| **该产生的订单才会执行生产排产** | `production_links.order_item_id` 外键；`link_order_item()` 要求订单已确认 |
| 询配码明细数量是**虚值**，排产数量**不与其对应** | `code_items.qty_reference` 仅为参考量，允许 0 / 任意值；`create_from_code_project()` **强制要求显式传 `qty_ordered`**，缺则抛 `ValidationError`，绝不复制虚值 |
| 排产数量和**产生订单的物资和数量**对应 | `order_items.qty_ordered`（实值）是唯一数量锚点；订单可新增物资（`source_code_item_id` 可空） |

| 域 | 实体 | 说明 | 数量语义 |
|---|---|---|---|
| ① 询报价·招投标 | `bid_projects` | 招投标项目头 | 金额统计 |
| ① | `bid_items` | 投标明细（原 `products` 迁移目标） | 询价数量（统计） |
| ② 询配码 | `code_projects` | 询配码项目/文件，**独立无来源外键** | — |
| ② | `code_items` | 询配码明细项（物资/规格/材质/标准/图号） | **`qty_reference` 虚值** |
| ③ 订单 | `orders` | 用户订单头，可指向来源询配码项目 | — |
| ③ | `order_items` | 订单明细（物资 + 数量），可指向来源询配码项 | **`qty_ordered` 实值** |
| ④ 生产排产 | `production_projects` | 生产项目/批次，可挂中标项目 | — |
| ④ | `production_tasks` | 工序任务（占位，P2 深化） | 工序完成量 |
| **打通** | **`production_links`** | **排产项目 ↔ 订单明细** | **`allocated_qty` 实值** |
| 通用 | `doc_sequence` / `audit_log` | 单号序列 / 审计留痕 | — |

### 4.1 关系基数

```
bid_projects 1───* bid_items          （只有 status=中标 可挂排产）
      │
      └───0..1──► production_projects.source_bid_project_id   ← 来源标签，不携带数量

code_projects 1───* code_items  （虚值，独立域）
      │ 1                 ▲
      │ 提交用户           │ source_code_item_id（可空）
      ▼ 0..*              │
orders 1───* order_items ──┘
                │ 1
                │ *  （多对多：一项可拆多批，一项目可挂多项）
                ▼
production_projects *──── production_links ────1 order_items
      │ 1
      └───* production_tasks
```

## 5. 打通设计（本次核心）

### 5.1 双轨分离：数量轨道 ≠ 溯源轨道

这是本版最重要的设计约束，**两条轨道不许混算**：

| 轨道 | 起点 | 终点 | 字段 | 用途 |
|---|---|---|---|---|
| **数量轨道（实值）** | `order_items.qty_ordered` | `production_links.allocated_qty` | `allocated_qty` | 守恒校验、排产执行、完工统计 |
| **溯源轨道（虚值）** | `code_items.item_code` | `order_items.source_code_item_id` → link 快照 | `code_no_snapshot` / `item_code_snapshot` / `qty_reference_snapshot` | 回答"哪个询配码的哪一项"、历史原貌 |
| **来源标签** | `bid_projects`（限中标） | `production_projects.source_bid_project_id` | — | 中标项目关联，不携带数量 |

> 硬规则：任何守恒公式、任何排产数量计算都**不得读取 `code_items.qty_reference`**。
> 代码里 `OrderService.create_from_code_project()` 强制要求显式传 `qty_ordered`，就是防止有人把虚值带进实值链路。

### 5.2 关联表 `production_links`

```sql
CREATE TABLE production_links (
    id                        INTEGER PRIMARY KEY AUTOINCREMENT,
    project_id                INTEGER NOT NULL REFERENCES production_projects(id) ON DELETE CASCADE,
    order_item_id             INTEGER NOT NULL REFERENCES order_items(id) ON DELETE RESTRICT,
    allocated_qty             REAL NOT NULL CHECK (allocated_qty > 0),
    order_no_snapshot         TEXT NOT NULL,   -- 订单号
    order_line_snapshot       TEXT NOT NULL,   -- 订单明细行 DD-...-02
    item_name_snapshot        TEXT,
    spec_snapshot             TEXT,
    code_no_snapshot          TEXT,            -- 来自哪个询配码项目（可空）
    item_code_snapshot        TEXT,            -- 来自该询配码的哪一项（可空）
    code_item_name_snapshot   TEXT,
    qty_reference_snapshot    REAL,            -- 虚值，仅展示对照
    created_by                TEXT,
    created_at                TEXT NOT NULL,
    UNIQUE (project_id, order_item_id)
);
```

**为什么用独立关联表**：支持一项目挂多项、一订单明细拆多批（`allocated_qty` 分账）、一次 `SUM` 得到已排/可排、以及建链瞬间的快照留存。

### 5.3 数量守恒（唯一公式）

```
可排量(订单明细) = order_items.qty_ordered − Σ production_links.allocated_qty
建链/改量校验：allocated_qty ≤ 可排量，否则 OverAllocationError
```

- 全部在同一事务内完成；`ON DELETE RESTRICT` 防止误删已排产的订单明细。
- 询配码虚值改成 0 或 99999 都**不影响**该公式（测试 `test_08` 验证）。

### 5.4 双向穿透

| 方向 | API | 返回 |
|---|---|---|
| 排产反查来源 | `TraceService.from_production(project_id)` | 订单号/明细行/物资/**实值数量/分配量** → 询配码项目/项号/**虚值（仅对照）** → 中标项目编号 |
| 询配码项正查去向 | `from_code_item(item_id)` | 被哪些订单下了多少（实值）、已排多少、`qty_reference_virtual` 对照 |
| 订单明细正查 | `from_order_item(item_id)` | 被哪些排产项目领用、各领多少、剩余可排 |
| 中标项目正查 | `from_bid_project(id)` | 关联了哪些排产项目 |
| 汇总 | `full_chain(project_id)` | 按订单、按询配码项目分组的完整来源清单 |

界面第 ⑤ Tab 就是这条链：**点一个排产项目，一眼看到它由哪张订单的哪一项构成，追到哪个询配码项目的哪一项，同时看到中标项目标签**；表格列名明确标注"实值数量"与"虚值(仅对照)"。

## 6. 数据库设计（摘要，全量见 `v2/core/schema.sql`）

| 表 | 主键 | 关键约束 |
|---|---|---|
| `bid_projects` | id | `doc_no` 唯一；`status` 由状态机校验 |
| `bid_items` | id | `(bid_project_id, line_no)` 唯一；`quote_ratio > 0`；`legacy_product_id` 保留旧库 ID |
| `code_projects` | id | `doc_no` 唯一；**无任何 bid/quote 外键** |
| `code_items` | id | `(code_project_id, item_code)` 唯一；`qty_reference` 无 CHECK（虚值） |
| `orders` | id | `doc_no` 唯一；`source_code_project_id` 可空（支持手工订单） |
| `order_items` | id | `(order_id, line_no)` 唯一；**`qty_ordered > 0`**；`source_code_item_id` 可空 |
| `production_projects` | id | `source_bid_project_id` 可空，服务层校验中标 |
| `production_tasks` | id | `finished_qty ≥ 0` |
| `production_links` | id | `(project_id, order_item_id)` 唯一；`allocated_qty > 0` |
| `doc_sequence` / `audit_log` | — | 事务取号 / 只增不改 |

索引覆盖 `status`、`source_*`、`order_item_id`、`project_id`。

## 7. 状态机与编码规则

| 实体 | 状态流 |
|---|---|
| 招投标项目 | `草稿 → 已报价 → 中标 / 未中标 / 作废` |
| 询配码项目 | `草稿 → 已提交 → 部分下单 → 已下单 → 关闭`（提交用户后才可下单） |
| 询配码明细项 | `待下单 → 已下单`（按是否被订单引用推导，**不看数量**） |
| 订单 | `草稿 → 已确认 → 已排产 → 生产中 → 已交付 → 关闭` |
| 生产项目 | `待排 → 已排产 → 生产中 → 完工 → 已交付` |

| 对象 | 格式 | 示例 |
|---|---|---|
| 招投标项目 | `ZB-YYYYMM-NNNN` | `ZB-202611-0001` |
| 询配码项目 / 明细项 | `XPM-YYYYMM-NNNN` / `<项目号>-<行号>` | `XPM-202611-0001-02` |
| 订单 / 明细行 | `DD-YYYYMM-NNNN` / `<订单号>-<行号>` | `DD-202611-0001-02` |
| 生产项目 / 工序 | `SC-YYYYMM-NNNN` / `<项目号>-T<序号>` | `SC-202611-0001-T01` |
