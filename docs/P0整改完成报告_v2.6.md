## 二、逐项说明

### P0-4 日志与崩溃捕获

**做了什么**
- `v2/core/applog.py`：`RotatingFileHandler`（5 MB × 5 份，UTF-8），格式 `时间 级别 [模块] 消息`；
- 三路捕获：`sys.excepthook`（主线程）、`threading.excepthook`（子线程）、`qInstallMessageHandler`（Qt 警告/绑定错误）；
- 启动写入上下文：版本、是否打包（frozen）、数据库路径、Python 版本、命令行参数；
- `log_exception(label, exc)` 供界面统一动作包装调用，`label` 即操作名；
- 菜单「维护 → 打开日志目录」；失败弹窗追加"详细堆栈已写入日志"。

**怎么用**
```
logs/app-20261107.log          # 源码运行：项目根 logs/
dist/ProductSuite_v2.2/logs/   # 打包运行：exe 同目录 logs/
```

**验收**：人为 `1/0` → 日志出现 `操作失败：<动作名>` + `ZeroDivisionError` + 完整 Traceback（测试 `test_22`）。
**边界**：只在真实控制台回显，管道/无控制台时不写 stderr（避免 cp936 乱码噪音）；日志不记业务字段明文。

### P0-2 结构版本 + 自动备份 / 恢复

**做了什么**
- `schema_meta(version, applied_at, note)`：新库直接写当前版本（2）；v2.5 老库以 1 为基线，逐级执行 `migrations.py`；
- 每级迁移独立事务，成功才写版本号，失败整体回滚；
- `Database.backup()` 用 `sqlite3.Connection.backup`（WAL 下安全，不锁业务）；
- `auto_backup()` 每日一次（同日已有 `-auto` 备份则跳过），`prune_backups(30)` 自动清理；
- `restore_from()`：先给现库打 `before-restore` 备份 → 关连接 → 清 `-wal/-shm` → 覆盖 → 重连 → 跑迁移；
- 菜单「维护 → 备份数据库 / 从备份恢复…」，恢复后提示重启。

**怎么用**
```
data/backup/erp-20261107-173316-before-migrate.db
data/backup/erp-20261107-173434-auto.db
```
恢复：维护 → 从备份恢复… → 选一份 → 确认（自动再备份现库）。

**验收**：备份文件可独立打开并查到数据；同日第二次 `auto_backup()` 返回 `None`；`prune(2)` 后只剩 2 份；`restore_from()` 后数据回到备份点且存在 `before-restore` 副本（测试 `test_11`~`test_14`）。
**边界**：备份是整库快照，不含外部绝对路径文件；恢复后必须重启界面。

### P0-3 附件相对路径 + 体检

**做了什么**
- 落库改存相对 `data/` 的 posix 路径（如 `订单排产附件/DDPS-202611-0001/磨损照片.png`）；
- `to_abs()` 读取时拼 `data_root`，历史绝对路径原样可用（向前兼容）；
- `repair_paths()` 把历史绝对路径批量裁成相对（幂等，二次执行返回 0）；
- `missing_files(order_id=None)` 体检：登记在册但磁盘缺失的附件清单；
- 菜单「维护 → 附件体检（缺失/路径修正）」，一次完成修正 + 缺失提示（前 12 条明细）。

**验收**：`shutil.copytree` 模拟整体换目录后 `to_abs()` 仍指向新目录且文件存在、`missing_files()` 为空（测试 `test_13b`）；删除文件后体检能报出（`test_13c`）。
**边界**：不在 `data/` 下的外部绝对路径保持原样，不误改、不搬移。

### P0-1 真实销售订单迁移

**源**：`销售订单汇总（24年7月-26年）.xlsx` · sheet《销售订单》22 列。

**映射**（全部可追溯）

| 源列 | 落库 | 说明 |
|---|---|---|
| 订单编号 | `orders.project_no` | 业务编号、分组键；系统单号另生成 `DD-YYYYMM-NNNN` |
| 需方单位 | `orders.customer` | 原样 |
| 订单状态 | `orders.status` | 源值沿用（已验收 / 发货中 / 待发货） |
| 价税合计 | `order_items.amount` → 订单头 `amount_total` | 行级原值；订单头 = Σ行金额（Q11 取汇总） |
| 交货日期 | `orders.required_date` | 取日期部分 |
| 物资数量 | `orders.item_qty_total` | **明细行数**（Q12 已拍板） |
| ERP订单编号 | `orders.erp_order_no` | 原样 |
| 产品代码 | `order_items.item_code` | 原样 |
| 产品名称 | `item_name` + `spec` | 按 `\` 分段：第一段名称、第二段型号；完整路径存 `remark` |
| 含税单价 / 数量 / 单位 | `unit_price` / `qty_ordered` / `unit` | 数量为唯一实值锚点，不改写 |
| 参数描述 | `param_desc` | **留空**（Q13 未拍板，不自动回填配置表） |

**结果**

| 校验项 | 结果 |

| 明细行数 | 734 |
| 数量合计 | 20,259.00 |

| 价税合计 ≠ Σ明细金额 | **0 单** |
| 一致性检查 | ✅ 通过（超排 0 / 来源混挂 0 / 孤立关联 0 / 一标多内部单 0） |

状态分布（按单）：已验收 269 / 发货中 23 / 待发货 14。

**怎么用**

## 四、操作速查

| 场景 | 操作 |
|---|---|
| 升级程序 | 备份 `data/` 整目录 → 覆盖新版本 → 把 `data/` 拷回 exe 同目录 |
| 每天自动备份 | 首次启动自动生成 `data/backup/erp-YYYYMMDD-HHMMSS-auto.db`，保留 30 份 |
| 误删/改错数据 | 维护 → 从备份恢复… → 选时间点 → 重启程序 |
| 程序报错/闪退 | 维护 → 打开日志目录 → 取最新 `app-*.log` 的 Traceback |
| 换电脑/改目录 | 直接拷整个程序目录；附件走相对路径，无需修库 |
| 附件丢失 | 维护 → 附件体检，查看缺失清单（登记仍在，可重新挂接） |
| 重跑数据迁移 | `py -m v2.migration.migrate_sales_orders --commit`（已存在则全部跳过） |
